Notes
  p95/worst_p95 matter more than mean: a locked framerate is lost at the
  tail, not on average.
  drop% is the number that matters: frames that missed the interval
  outright (>1.5x budget) rather than merely exceeding it. This is what
  is felt as stutter when turning the head.
  miss% is NOT a stutter metric. Held at the refresh rate, frametime
  sits exactly ON the budget, so jitter puts ~half the frames just above
  it - the 2026-08-03 run read 33-44% miss in a scene that felt perfect.
  Read it as a margin gauge instead: ~0% means real headroom, ~30-50%
  means sitting on the cap, >80% means genuinely over budget.
  spread is max-min of the per-visit mean. If spread is comparable to the
  gap between two presets, those presets are not distinguishable in this
  scene and the ranking between them means nothing.
  drift is ascending-sweep mean minus descending-sweep mean. Near zero is
  a stable scene. Large and same-signed across every preset means the
  session drifted and the absolute numbers are not comparable to another
  session - though the ranking within this one still survives, which is
  the reason for reversing alternate sweeps.
  settle_s is time from the API call to a stable frametime.
  rbfail counts visits where GetUpscalePreset() did not return the value
  just set - if non-zero, the API is not doing what it claims.
  failed counts visits that never applied and so produced no frames.
  They are excluded from every average above rather than being averaged
  in as 0 ms. A non-zero value means 'visits' is smaller than the number
  of sweeps, so the remaining averages rest on fewer samples.
